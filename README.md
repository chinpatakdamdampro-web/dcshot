# DiscordShot

A Paper/Spigot plugin that adds a `/screenshot` Discord slash command. Type
`/screenshot <x> <y> <z> [world]` in Discord and the bot posts back a 3D render of that
spot, generated by driving a headless browser against your server's
[BlueMap](https://bluemap.bluecolored.de/) web map.

No virtual GPU needed on the host - BlueMap's web renderer runs in software (SwiftShader)
inside a headless Chromium, which this plugin ships and drives for you.

[![Build](../../actions/workflows/build.yml/badge.svg)](../../actions/workflows/build.yml)

## How it works

1. Drop the built jar into your server's `plugins/` folder.
2. Paste your Discord bot token into `plugins/DiscordShot/config.yml`.
3. Restart the server. Use `/screenshot 100 64 -200 world` in Discord.

Under the hood: JDA runs the Discord bot side, and Playwright drives a headless Chromium
pointed at your BlueMap URL, waits for the 3D scene to draw, screenshots the page, and
uploads the image back to the channel - all off the main server thread.

## Requirements

- A Paper or Spigot server, Minecraft 1.21.x (Java 21+ to run the server itself).
- [BlueMap](https://github.com/BlueMap-Minecraft/BlueMap) installed and running, with its
  web server reachable from wherever this plugin runs (same machine, by default).
- A Discord bot application + token (free, see below).
- Enough RAM/CPU headroom to run one headless Chromium instance briefly per screenshot.

## 1. Get a Discord bot token

1. Go to the [Discord Developer Portal](https://discord.com/developers/applications) →
   **New Application**.
2. Open the **Bot** tab → **Reset Token** → copy it. This goes in `bot-token`.
   You do **not** need to enable any Privileged Gateway Intents - this bot only
   handles slash commands, which don't require them.
3. Open **OAuth2 → URL Generator**. Check scopes `bot` and `applications.commands`.
   Under **Bot Permissions**, check at least `Send Messages`, `Embed Links`, and
   `Attach Files`.
4. Open the generated URL, pick your server, and authorize the bot.
5. (Optional) Turn on Discord's Developer Mode (User Settings → Advanced), then
   right-click your target channel or server to copy IDs for `allowed-channel-id` /
   `guild-id`.

## 2. Build it

### Option A - GitHub Actions (recommended, matches "so it builds on the repo")

1. Unzip this project and push it to a new GitHub repository (see commands below).
2. GitHub Actions builds it automatically on every push - check the **Actions** tab.
3. Open the finished run → download the `DiscordShot-plugin` artifact → unzip it to get
   `DiscordShot-1.0.0.jar`.

```bash
# from a Codespace, or anywhere with the zip extracted:
git init
git add .
git commit -m "Initial commit: DiscordShot plugin"
git branch -M main
git remote add origin https://github.com/<you>/<your-repo>.git
git push -u origin main
```

That's it - the workflow in `.github/workflows/build.yml` runs `mvn package` for you and
uploads the jar as a build artifact.

### Option B - build locally

```bash
mvn package
# jar is at target/DiscordShot-1.0.0.jar
```

The default build bundles Playwright's browser driver for **every** OS (Windows, macOS,
Linux x64/arm64), so the jar works no matter what OS your Minecraft server runs on - at
the cost of a larger file (100+ MB). If you know exactly which OS your server uses, you
can build a much smaller, single-OS jar instead:

```bash
mvn package -Plinux-x64    # or: -Plinux-arm64, -Pwindows-x64
```

## 3. Install the browser (one-time)

Playwright needs an actual Chromium binary, which isn't bundled in the jar itself (that
would make it enormous). After building, run this **once**, as the same OS user that runs
your Minecraft server:

```bash
java -jar DiscordShot-1.0.0.jar install chromium
```

This downloads Chromium into a shared cache the plugin will find automatically at
runtime. If you ever see a "browser not found" error in Discord, re-run this command.

## 4. Configure and start

Drop the jar into `plugins/`, start the server once so it generates
`plugins/DiscordShot/config.yml`, then edit it:

| Key | What it does |
|---|---|
| `bot-token` | Your Discord bot token (keep this secret!). |
| `allowed-channel-id` | Restrict `/screenshot` to one channel. Empty = any channel. |
| `render-method` | Only `"BLUEMAP"` is implemented right now. |
| `bluemap-url` | Where BlueMap's web server is reachable from this machine. |
| `guild-id` | Register the slash command instantly in one server (empty = global, slower to appear). |
| `public-map-url` | Public BlueMap link added to each screenshot, if you have one. |
| `default-world` | World used when no world is given in Discord. |
| `map-ids` | Only needed if a world's BlueMap map ID differs from its Minecraft name. |
| `screenshot.*` | Image size, camera angle/distance, wait time, PNG/JPEG. |
| `limits.*` | Queue size and per-user cooldown. |
| `browser.executable-path` | Point at a system-installed Chrome/Chromium instead of Playwright's own. |

Restart the server and try `/screenshot 100 64 -200 world` in Discord.

## Troubleshooting

- **"Chromium isn't downloaded yet"** - run the `install chromium` command from step 3.
- **Blank / half-rendered screenshots** - increase `screenshot.render-wait-ms`; the server
  has no real GPU, so the 3D scene can take longer than the ~1.5s a real GPU would need.
- **Timed out waiting for BlueMap** - make sure `bluemap-url` is reachable *from the
  machine this plugin runs on* (not just from your own browser), and that BlueMap's web
  server is actually running.
- **BlueMap's menus/sidebar show up in the picture** - BlueMap's exact HTML changes
  between versions. Open BlueMap in a normal browser, inspect the overlay elements you
  want hidden, and set `screenshot.hide-ui-css` to a CSS rule that hides them.
- **The camera view looks wrong** - BlueMap's URL format has changed across versions in
  the past. Open BlueMap manually, move the camera, and compare the address bar to
  `view-template` in config.yml; adjust the template to match if needed.

## Maintenance notes

- `pom.xml` pins specific versions of Paper, JDA, and Playwright that were confirmed to
  exist at the time this was written. Minecraft, JDA, and Playwright all ship regularly -
  bump these versions occasionally (links are right above them in `pom.xml`).
- Threading: one dedicated thread owns the headless browser (Playwright's objects aren't
  safe to share across threads), Bukkit/world calls always hop back onto the main server
  thread, and everything Discord-facing goes through JDA's own async `RestAction`s - so
  nothing here blocks the main server thread.
